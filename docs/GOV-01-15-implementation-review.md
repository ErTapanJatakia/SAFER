## Status definitions

- **Implemented foundation:** the named capability exists in source, but one or more production, validation or operational gates remain.
- **Partial:** a constrained demonstration or workflow exists, but important parts of the agreed capability are absent.
- **In progress:** work is documented or partly implemented, but the required end-to-end reconciliation or assurance has not been completed.
- **Deferred:** deliberately not implemented pending an explicit decision or prerequisite.

## UI/OPS review changes carried into the stacked implementation

- UI-01: Owner registry now provides local search, status filtering and counts for the maximum 100 records returned by the existing registry endpoint. It is not platform-wide analytics.
- UI-07 / GOV-03: Owner PMC and tenant member invitation screens surface the one-time invitation ID, recipient and expiry context, with clipboard/manual-copy guidance. Delivery remains manual; Super Admin acceptance still creates pending activation.
- UI-12: tenant audit view/API now support inclusive date filters, a default page size of 50 (maximum 100), tenant-bound cursor validation and load-older navigation. Text search remains limited to loaded pages.
- OPS-07 / GOV-03: suspended manageable memberships can be reactivated by authorised Super Admin/Admin actors. The status transition and audit event are committed in one transaction.
- OPS-08 / GOV-06: Activity tab visibility now matches the server-side `audit:read` permission; it is not shown to Manager or Employee roles.
